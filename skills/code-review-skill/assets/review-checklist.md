# Code Review Quick Checklist

Quick reference checklist for reviews in this repo. Bullets marked *(check PROJECT_MAP.md)* need
this repo's actual stack/convention filled in from `PROJECT_MAP.md` (generated by the
`project-map` skill) — the parenthetical examples are illustrations, not universal requirements.

## Pre-Review (2 min)

- [ ] Read PR description and linked issue (tracker per `PROJECT_MAP.md` §13)
- [ ] Check PR size (<400 lines ideal)
- [ ] Verify CI status: lint, type-check, tests passing (gates per `PROJECT_MAP.md` §8)
- [ ] Understand the business requirement, in the repo's own domain terms

## Architecture & Design (5 min)

- [ ] Solution fits the problem
- [ ] Consistent with existing patterns *(check PROJECT_MAP.md §4/§11 — e.g. Either/UnitOfWork on a NestJS backend, Server/Client boundary on Next.js)*
- [ ] No simpler approach exists
- [ ] Change lives in the right location, per `PROJECT_MAP.md` §4's "what to create → where it goes" table

## Logic & Correctness (10 min)

- [ ] Edge cases handled
- [ ] Null/undefined checks present
- [ ] Off-by-one errors checked
- [ ] Race conditions considered (concurrent/async writes, background job consumers)
- [ ] Error handling complete, following this repo's documented pattern
- [ ] Correct data types used, no untyped escape hatch (`any` or equivalent)

## Security (5 min)

- [ ] No hardcoded secrets
- [ ] Input validated at the boundary (DTO/schema per this repo's convention)
- [ ] SQL injection prevented (parameterized queries / ORM)
- [ ] XSS prevented (no unsanitized raw-HTML injection)
- [ ] Authorization checks present
- [ ] Sensitive data protected (not logged, not shipped to the client)

## Performance (3 min)

- [ ] No N+1 queries
- [ ] Expensive operations optimized
- [ ] Large lists paginated
- [ ] No obvious memory leaks (uncleaned effects/listeners/timers)
- [ ] Caching considered where appropriate

## Testing (5 min)

- [ ] Tests exist for new code, per `PROJECT_MAP.md` §6 convention
- [ ] Edge cases tested
- [ ] Error cases tested
- [ ] Tests are readable and deterministic

## Code Quality (3 min)

- [ ] Clear variable/function names
- [ ] No code duplication
- [ ] Functions do one thing
- [ ] Non-obvious logic has a comment explaining *why*
- [ ] No magic numbers/strings replacing an existing enum

## Documentation (2 min)

- [ ] API docs/decorators present for new/changed endpoints, if this repo has that convention
- [ ] Breaking changes noted in the PR description
- [ ] Complex logic explained where genuinely non-obvious

## Severity Labels

| Label | Meaning | Action |
|---|---|---|
| 🔴 `[blocking]` | Must fix | Block merge |
| 🟡 `[important]` | Should fix | Discuss if disagree |
| 🟢 `[nit]` | Nice to have | Non-blocking |
| 💡 `[suggestion]` | Alternative | Consider |
| 📚 `[learning]` | Educational comment | No action needed |
| 🎉 `[praise]` | Good work | Celebrate! |

## Decision Matrix

| Situation | Decision |
|---|---|
| Critical security issue | 🔴 Block, fix immediately |
| Breaking change without migration/rollout plan | 🔴 Block |
| Multi-step write without this repo's transaction/unit-of-work pattern | 🔴 Block |
| Missing error handling | 🟡 Should fix |
| No tests for new code | 🟡 Should fix |
| Style preference already covered by this repo's lint/format tool | 🟢 Non-blocking |
| Minor naming improvement | 🟢 Non-blocking |
| Clever but working code | 💡 Suggest simpler |

## Red Flags

Watch for these patterns:

- `// TODO` in production code
- Debug prints left in code (check `CLAUDE.md` for whether this repo bans `console.log`/equivalent in favor of a project logger)
- Commented-out code
- Untyped escape hatch (`any` or equivalent) in a typed language
- A lint-suppression comment (`@ts-ignore`, `# noqa`, …) without a justification
- Empty catch blocks
- Unhandled error branch (this repo's `Either`/`Result` type, or an unchecked exception path)
- Arbitrary inline styling instead of this repo's design-system tokens, if it has one
- Magic numbers/strings
- Copy-pasted code blocks
- Missing null checks
- Hardcoded URLs/credentials
- A relative-import chain (`../../../`) where this repo has an alias convention instead
